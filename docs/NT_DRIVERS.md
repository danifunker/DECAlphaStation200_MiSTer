# Windows NT 5.0 (Windows 2000) Alpha driver references

The binaries and listings live in `scratch/nt_drivers/` (not in git).

These are Microsoft and Digital binaries, kept for reverse engineering only. **Don't redistribute them or commit them
to a public repository** (add `scratch/nt_drivers/*/bin/` to `.gitignore` if this becomes a public git repo).

Sources:
- `2072_rc1/`: RC1, from `scratch/isos/5.00.2072.1_alphafre_client-professional_retail_en-us-W2KPROA_USA-x04-95185.iso`
  (MD5 `cf2346bb29d3b5c05f8d51bea76afd64`, verified against archive.org). Files come from `\ALPHA` and `\ALPHA\DRIVER.CAB`.
- `1877_beta2/`: Beta 2, single files fetched from the archive.org copy of
  `5.00.1877.1_alphafre_client-workstation_retail_en-us-NTWKS50A-03-87871.iso`. Use them for diffing against RC1;
  every TGA, TGA2 and HAL binary differs between the two builds.

Each build folder has `bin/` (the binaries), `SHA1SUMS`, and `disasm/`, which is generated by
`python3 -I tools/pe_alpha_disasm.py <outdir> <files>`. For each binary, `disasm/` holds:
- `*.dis.txt`: EV4 disassembly with function labels from the `.pdata` function table, import names on IAT loads,
  absolute addresses resolved to labels or strings, and named call targets.
- `*.info.txt`: sections, imports, exports, and the full `.pdata` table (begin, end, handler, data, prolog end).
- `*.strings.txt`: ASCII and UTF-16 strings with virtual addresses.

## What to look at, by core component

| Core component | Binaries | Why |
|---|---|---|
| **TGA (ZLXp-E, 21030) video** | `tga.sys` (miniport), `tga.dll` (display driver) | The miniport's ~100 `VideoPortWriteRegisterUlong`/`ReadRegisterUlong` calls show the register set and init sequence NT really uses. The display DLL shows which 2D engine modes (copy/fill/stipple) GDI drawing needs |
| TGA2 (PowerStorm 3D30/4D20) | `tga2.sys`, `tga2.dll`, `tga2.inf` | For comparison only; see the note below |
| S3 Trio64 (fallback) | `s3m.sys`, `s3mtrio.dll` | |
| VGA (Setup / safe mode) | `vga.sys`, `vga.dll`, `videoprt.sys` | `videoprt.sys` holds the x86 int 10h emulation hooks used for BIOS-driven cards |
| **Platform: 21071 chipset, interrupts, PCI, clock, DMA** | `halavant.dll` | The AS200/400 HAL. It shows the CSR programming, PCI config access, the SIO/8259 interrupt dispatch, interval timer use, and how scatter/gather DMA windows are set up |
| CPU, PALcode interface | `ntoskrnl.exe` | Kernel side of the NT PALcode calls; 5,153 functions, 1,209 exports |
| ARC firmware interface | `osloader.exe`, `SETUPLDR` | Raw COFF ROM images loaded by ARC at 0x80600000 (entry 0x806002D0). They show which ARC firmware calls and configuration-tree data NT needs from the console |
| SCSI 53C810 | `symc810.sys`, `symc8xx.sys`, `scsiport.sys` | The SCRIPTS processor features the driver relies on |
| Ethernet 21040 | `dc21x4.sys` | |
| PC peripherals behind the SIO | `i8042prt.sys`, `fdc.sys`, `flpydisk.sys`, `serial.sys`, `parport.sys` | |
| Audio | `sndblst.sys` | Sound Blaster driver. I found no WSS/AD1848 driver in RC1's `DRIVER.CAB` (searched for snd/wss/ad18/msnd), so the AS200 sound card may need NT 4.0's driver instead |
| INFs | `display.inf`, `hal.inf`, `tga2.inf` | Device IDs and registry settings |

## TGA vs TGA2: why the core targets the original TGA
- The AS200 **ARC 4.58 firmware only recognises the ZLXp-E1/E2/E3 (TGA)**. TGA2 is absent from its strings, so NT Setup and boot can't display on a TGA2 card. SRM 7.0 does know TGA2, so it would work for Digital UNIX and VMS only.
- In the NT 5 builds, `tga.sys` is in every Alpha build. `tga2.sys` first appears in Beta 2 (1877) and is absent from Beta 1 (1671) and 1855.
- NT 3.51 ships only the ZLXp (TGA) driver. TGA2 needed a separate DEC driver kit.
