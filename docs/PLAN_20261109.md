# Plan (merged, user-ordered 2026-11-09)

The OS survey of `docs/OPUS_RESUME_PROMPT.md` (section 1) is done: every OS on its list installs and boots
from disk (`docs/gaps.md`, OS table); Tru64 5.1B-4 lacks only a verified login and a ZIP. The video phase
of that plan was never started, and OS sweep 2 (`docs/FABLE_OS_SWEEP2_RESUME_PROMPT.md`) found that X on
every Unix fails on interrupt and frame-buffer problems, not on the drawing engine. This is the merged
order, decided by the user on 2026-11-09:

1. **SRM P0 boot failure** (gaps.md "SRM boots: the first console open fails"): the biggest blocker,
   ~9 of 10 boots typed at an idle `>>>` fail; boots typed during SRM's restart pass. Compare the two.
2. **X on the Unixes**, in this order:
   - the 8259 cascade (spurious IRQ 15 leaves master IR2 in service; Tru64 X, likely the SCSI hangs):
     `tb_isa_pic`, fix, re-test Tru64 4.0G's X and FreeBSD's de0 boot loop/panic;
   - the 53C810 ISTAT.ABRT and the GP timer rate (`tb_ncr810`);
   - the TGA frame buffer as X mmaps it (NetBSD wsfb draws nothing): TGA trace of the Xorg start, fix;
   - the ZLXp-E1 completed, **8 bpp stays**: the TGA cursor (CCBR/CXYR/VVVR<2>, NetBSD's X), line mode
     0E, the Bt485 paths X uses, ICS1562 modes. A 32-bpp E2/E3 or another card is deferred until the
     rest of the core is better known (user).
3. **NT 4.0 / Windows 2000 video**: the Notepad++ artefacts (trace-and-replay, `docs/FABLE_RESUME_PROMPT.md`).
4. `dbg_trace`/`dbg_overlay` behind a compile switch (release builds without them; ~960 LUTs, 33 M10Ks).
5. Handed to another agent after the X work: finish Tru64 5.1B-4, flash save-back and the ARC default
   boot entry, CPU speed (ubench first), NVRAM/CMOS persistence, machine checks, the rest of gaps.md.

Rules unchanged: report only what a test showed; small local commits; never push, delete or overwrite an
installed image without asking; ask before changing Main or the boards' configuration.
